# Перенос Varania OS с x86 на amd64

## Исходное состояние

Версия 2019 года была монолитным 32-битным FASM-ядром:

- protected mode и двухуровневые таблицы страниц;
- база ядра `0xFFC00000`;
- 8-байтовые 32-битные шлюзы IDT;
- собственные стековые макросы `proc/stdcall`;
- фиксированное предположение о 32 MiB RAM;
- VGA, PIC/PIT, клавиатура и `int 0x30`.

Экспериментальные `cmd.inc`, `mouse.inc`, `task/*` и часть TTY не подключались
к образу и содержали незавершённые ссылки. Они сохранены в дереве как материал
для сравнения, но активный код расположен в `src/kernel/amd64/`.

## Основные изменения

| Область | Было | Стало |
|---|---|---|
| Режим CPU | 32-bit protected mode | 64-bit long mode |
| Адресация | 2 уровня, 32-битные записи | PML4, 4 уровня, 64-битные записи |
| Ядро | `0xFFC00000` | `0xFFFF800000000000` |
| IDT | 256 × 8 байт | 256 × 16 байт |
| Возврат из IRQ | `iret` | `iretq` |
| Аварийный стек | отсутствовал | TSS64 + IST1 для #DF |
| ABI | пользовательские стековые макросы | регистры System V AMD64 |
| PMM | жёсткие 32 MiB | пригодные области E820, лимит 1 GiB |
| Тестирование | ручное окно QEMU | формат + headless boot marker |

## Ошибки, найденные в незавершённом порте

Ниже перечислены не косметические отличия, а причины реальных тройных сбоев:

1. Paging включался без `CR4.PAE` и `IA32_EFER.LME`.
2. Записи PML4/PDPT/PD имеют размер 8 байт, но смещения считались с шагом 4.
   Например, `PML4[256]` находится по смещению `2048`, не `1024`.
3. Очищалась лишь половина каждой 4096-байтовой таблицы: 512 `stosd` вместо
   1024.
4. Физический `0x100000` использовался как большая страница 2 MiB. Он не
   выровнен на 2 MiB; верхняя половина теперь построена из обычных PTE.
5. 16-байтовый дескриптор TSS был разложен в неверном порядке и имел размер
   GDT 48 вместо 56 байт.
6. Поля `RSP0` и `IST1` записывались не по смещениям формата TSS64 (`+4` и
   `+36`).
7. Код E820 принимал ключ продолжения BIOS в `EBX` за число записей. Теперь
   количество ведётся отдельно, проверяются подпись и граница буфера.
8. Битовая карта старого PMM могла выделить кадр, в котором лежала сама.

## Сохранённая функциональность

Порт не ограничивается сообщением «hello world». Он сохраняет основную учебную
цепочку исходной системы: вывод на VGA, исключения, аппаратный таймер,
клавиатуру, физические кадры, отображение страниц и `int 0x30`. Как и раньше,
ядро выделяет кадр, копирует туда маленькую программу и передаёт ей управление;
теперь этот путь полностью 64-битный.

## Почему активные модули вынесены отдельно

Автоматическое преобразование каждого `EAX` в `RAX` создало бы код, похожий на
64-битный только внешне. Различаются формат IDT/TSS, кадр исключения, правила
`push/pop`, канонические адреса и ABI. Поэтому рабочий путь переписан в
`src/kernel/amd64/`, а исторические файлы оставлены рядом для построчного
сравнения и будущих учебных заданий.
